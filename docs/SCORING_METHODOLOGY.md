# 评分方法

- 模型：`competition-value`
- 版本：`1.0.0`
- 生效日期：2026-11-01
- 数据文件：`data/scoring-models/competition-value-1.0.0.json`
- 代码：`src/lib/domain/scoring.ts`、`src/lib/domain/ranking.ts`
- 测试：`tests/unit/scoring.test.ts`、`tests/unit/ranking.test.ts`

## 1. 目的与非目标

评分用于帮助学生比较竞赛的技术深度、认可度、实践价值、竞争难度、成长收益与成本，并解释差异。

它不是：

- 官方排名或主办方认定；
- 对保研、就业、获奖结果的预测；
- 对个人能力的评价；
- 对不同领域、不同年份竞赛的绝对比较。

外部竞赛目录/榜单（包括高校常用的“A 类”目录）**不参与评分**。它们只作为竞赛详情中的检索线索，不能被当作认可度、技术深度、竞争难度或官方认证的替代证据；评分引擎与排名引擎都不读取该字段。

## 2. 六个维度

所有维度归一化到 0–100，权重之和为 1。

| 维度             | ID                   | 权重 | 定义                                           |
| ---------------- | -------------------- | ---- | ---------------------------------------------- |
| 技术深度         | `technical_depth`    | 25%  | 技术复杂度、工程整合、理论要求、问题开放度     |
| 行业/学术认可度  | `recognition`        | 20%  | 主办方与赛制可验证信息、跨机构/行业影响        |
| 实践与创新价值   | `practical_value`    | 20%  | 可验证作品、工程能力、可复用成果               |
| 竞争难度         | `competitiveness`    | 15%  | 资格、赛制、公开规模、获奖比例（数据可用时）   |
| 学习成长收益     | `growth_value`       | 15%  | 技能覆盖、项目积累、迁移与复盘价值             |
| 参与成本可承受性 | `cost_accessibility` | 5%   | 费用、时间、设备、团队组织成本；成本越低分越高 |

权重属于平台方法论，不是客观真理；调整必须版本化并记录原因。

## 3. 公式

```text
total_score = Σ(dimension_score × dimension_weight)
```

- `dimension_score ∈ [0, 100]`
- `Σ dimension_weight = 1`（允许 1e-9 浮点误差）
- 总分保留两位小数存储，页面显示一位小数

示例（全国大学生数学建模竞赛，模型 1.0.0）：

```text
82×0.25 + 90×0.20 + 85×0.20 + 88×0.15 + 90×0.15 + 55×0.05
= 20.50 + 18.00 + 17.00 + 13.20 + 13.50 + 2.75
= 84.95
```

用户可在竞赛详情页展开每个维度的理由与证据等级。

## 4. 缺失数据

- 未知维度不记为 0 或 100。
- 不把缺失维度悄悄从分母移除后仍使用原始权重。
- 部分维度已知时，按已知权重重新归一化得到“暂定分”，同时显示覆盖率。
- 暂定分不参与正式排名。
- 正式排名要求全部维度有分数与依据。
- 资料不足的条目进入“未进入正式排名”列表，并显示具体原因。

## 5. 正式排名准入

同时满足：

1. `verification_status = verified`，且有 official/organizer/institutional 来源；
2. `scores.review_status = approved`，且记录 `reviewed_at` 与 `reviewer_role`；
3. `scores.confidence_level` 至少为 `medium`；
4. 六个维度全部有分数与理由（覆盖率 100%）；
5. 最后核验时间不超过 18 个月；
6. 评分引用的模型版本与当前模型一致。

不满足的条目不参与排名；平台不会用暂定分填充榜单。

## 6. 证据等级与置信度

| 等级   | 含义                                         |
| ------ | -------------------------------------------- |
| high   | 关键事实有官方来源，评分理由与来源齐全       |
| medium | 关键事实有来源，但部分依据来自估算或社区经验 |
| low    | 缺少关键来源，不能参与正式排名               |

证据等级与总分分开展示，不合成“权威指数”。单个维度证据为 low 时，整体置信度不应为 high。

## 7. 并列规则

- 总分相同（容差 1e-9）共享名次；
- 下一名次跳过被占用的位置（例如 1、1、3）；
- 同分不按名称、更新时间或主观看感制造差异；
- 页面标注“并列”。

## 8. 版本化与变更

- 模型文件包含 `version`、`effective_from`、`changelog`。
- 权重、维度定义或准入规则变化必须提升版本，并记录原因与生效日期。
- 旧评分保留 `model_version`；切换模型时重新评分，不静默覆盖。
- 页面展示模型版本；排行榜按当前模型计算。

## 9. 防止操纵

首版不开放无身份约束的即时打分。使用：

- PR 审核与公开修改历史；
- Issue 记录纠错依据；
- 维护者审核；
- 评分方法版本化；
- 对争议分数附加说明，而不是删除合理异议。

未来动态评分需考虑账户、限频、重复评分、异常检测、申诉与隐私。

## 10. 已知限制

- 评分是编辑初评，存在主观性；首版尚未经过领域专家大规模复核。
- 成本维度在缺少官方费用时使用保守估计，证据等级通常为 medium/low。
- 认可度依据官网可核验信息，不采用宣传性“排名”。
- 跨领域比较容易误导；排行榜提供领域筛选，但仍需用户自行判断目标匹配。
- 样本量字段在多数竞赛中为 null；平台不伪造参赛人数或获奖比例。
- 竞赛规模数据（如官网公布的报名队数）用于证据摘要，不作为统计抽样样本。

## 11. 如何复现

```bash
npm test -- tests/unit/scoring.test.ts tests/unit/ranking.test.ts
npm run data:validate
npm run build
```

评分引擎为纯函数，不依赖当前时间（除非显式传入 `asOf`）；排名结果在相同数据与模型版本下可复现。

## 12. 变更流程

1. 在 Discussions 或 Issue 提出变更理由与预期影响。
2. 更新 `data/scoring-models/` 新版本文件（不直接改旧版本）。
3. 更新受影响竞赛的 `scores.model_version` 与 `weighted_score`。
4. 更新本文件与 `CHANGELOG.md`。
5. 运行全部检查，PR 中说明变更前后对比与风险。
6. 维护者与领域评审复核后合并。
