TechCompetitionHub 编程 Agent 项目约束



项目目标



开发 TechCompetitionHub，一个面向大学生与科技竞赛参与者的开源成长平台。首版使用 React、TypeScript、Vite、GitHub Pages、GitHub Discussions，以及 JSON/Markdown 文件。



四类功能需要均衡建设：



1\. 竞赛目录、筛选与可解释排行榜。

2\. 社区经验、项目案例和资源分享。

3\. 技能图谱与技能关联。

4\. 基于规则的学习及竞赛成长规划。



执行规则



1\. 开始前检查仓库目录、Git 状态、现有文档、依赖版本及当前测试结果。

2\. 先输出当前任务的实施计划、涉及文件、依赖和验收方法。

3\. 严格遵守现有架构，不得未经说明替换技术栈或引入大型依赖。

4\. 数据模型、JSON Schema、TypeScript 类型和数据校验规则必须保持一致。

5\. 业务组件不得直接读取分散的 JSON 文件，统一通过数据 Repository 层访问。

6\. 禁止编造真实竞赛、官方来源、用户评价、评分数据或验证结果。所有演示数据必须明确标注。

7\. 所有评分、筛选和成长规划逻辑必须可解释、可测试、结果可复现。

8\. 不引入后端、付费 API、账号系统或秘密凭据，除非项目负责人另行批准。

9\. 不使用 any 绕过类型检查，不通过删除测试或降低检查标准解决构建问题。

10\. 不覆盖用户已有修改，不擅自清理无关文件，不直接向主分支推送未经批准的变更。



每项任务的执行流程



A. 检查仓库状态与任务依赖。

B. 明确任务范围和验收标准。

C. 先实现最小可用版本。

D. 添加对应测试和必要文档。

E. 执行 Lint、类型检查、测试、数据校验和构建。

F. 修复本任务引入的问题。

G. 汇报修改文件、关键设计、实际测试结果、未完成事项及风险。



完成标准



只有实际运行并通过的检查才能报告为通过。无法运行的检查必须明确说明原因，不得推测通过。



每次提交应保持任务边界清晰，优先使用小型、可审查的变更。发现架构性问题时先报告并提出方案，不得自行大规模重构。



输出格式



\- 任务目标

\- 仓库现状

\- 实施计划

\- 修改文件

\- 设计决策

\- 测试命令与实际结果

\- 验收项逐条状态

\- 遗留问题与下一步建议
