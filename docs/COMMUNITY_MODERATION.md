# 社区与论坛治理

本文件适用于 GitHub Discussions、Issue、PR 讨论与站内“参赛评价”审核。它补充 `CODE_OF_CONDUCT.md` 与 `.github/DISCUSSION_GUIDE.md`，不替代 GitHub 的平台规则。

## 角色

- **维护者**：合并代码/数据、处理安全与隐私问题、最终解释规则。
- **版主/审核者**：按本文件处理帖子、评价与争议；可以编辑敏感信息、锁定或移除内容。
- **贡献者**：发帖、提问、提交 Issue/PR、提交参赛评价。
- **参与者**：阅读、投票、在讨论中提供有证据的补充。

## 论坛分类边界

| 分类          | 适合                         | 不适合                  |
| ------------- | ---------------------------- | ----------------------- |
| Announcements | 版本、数据、规则、维护公告   | 提问、组队、项目宣传    |
| Q&A           | 竞赛规则、选择、技术问题     | 无来源断言、招生承诺    |
| Show and tell | 复盘、项目展示、失败教训     | 纯广告、未授权材料      |
| General       | 组队、跨校协作、综合讨论     | 数据纠错（走 Issue/PR） |
| Ideas         | 产品、数据字段、可访问性建议 | 重复灌水、人身攻击      |
| Polls         | 公开、非误导性的社区投票     | 竞赛“谁更强”、敏感信息  |

## 处理阶梯

1. **提醒/编辑**：标题不可搜索、缺少来源、包含非必要个人信息。
2. **锁定**：讨论偏离主题、重复争吵、已得到结论但持续刷屏。
3. **移除**：违规内容、隐私泄露、广告、抄袭、操纵投票。
4. **限制参与**：重复违规、骚扰、假冒身份、恶意破坏。
5. **升级**：涉及安全漏洞、法律威胁或未成年人隐私时，按 `SECURITY.md` 私下处理。

处理时优先保护隐私与安全；能在不公开敏感内容的情况下纠错，就不要重复公开敏感细节。

## 参赛评价审核

站内“提交参赛评价”通过 GitHub Issue 进入审核，维护者审核后写入 `data/reviews/`。审核规则：

- 必须有 `consent_public: true`；否则不得批准。
- 参加过竞赛的评价必须填写赛道与年份；学校可以留空。
- 不把评价中的自述当作已验证事实；不因评价内容修改平台六维评分或排名。
- 检查是否包含手机号、身份证、真实姓名、住址、未公开的群聊截图或未授权材料。
- 与竞赛主办方/培训机构的利益关系应披露；未披露的推广内容按广告处理。
- 可以修正明显的格式/敏感信息，不改变评价的核心意思；重大修改需征得作者同意。
- `approved` / `rejected` 都应记录 `reviewed_at` 与 `notes`；拒绝时说明可公开的理由。

## 数据纠错与论坛的分工

论坛适合讨论“为什么”“怎么理解”；**确定性事实纠错**必须走 Issue/PR，附官方来源与访问日期。论坛帖子不自动成为数据来源，也不因为多人赞同而变成事实。

## 申诉

对处理有异议，可通过仓库 Issue 或 `CODE_OF_CONDUCT.md` 中的渠道说明，附链接与事实。不要在原帖反复刷屏或人身攻击版主。维护者应在合理时间内复核；涉及隐私的内容优先私下处理。

## 记录

- GitHub 的编辑、删除、锁定与 block 记录由平台保留。
- 数据/评价审核结果记录在对应 JSON 的 `reviewed_at`、`notes` 与 Git 历史中。
- 不公开举报者身份；不把举报内容直接贴到讨论区。
